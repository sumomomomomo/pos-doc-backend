# Task 7: Bounded first-page PDF rendering foundation

## Objective

Implement the production-quality internal component that prepares the first page of one persisted PDF for later OCR.

The component must:

1. Load the `pos_document` and its PDF `storage_object` metadata in a short read-only SQLite transaction.
2. Stream the PDF object from MinIO to an owned temporary file while enforcing its declared size, SHA-256, and a configured maximum.
3. Render page index `0` to a bounded RGB PNG using Apache PDFBox.
4. Return an `AutoCloseable` handle containing the PNG path and safe metadata.
5. Delete every temporary PDF and PNG on every success and failure path.

This task is a rendering foundation only. It must not yet invoke the renderer from RabbitMQ, OCR the image, classify documents, extract insurance fields, or persist the temporary PNG.

## Why the PNG is temporary

The first-page image contains the same PII as the source PDF. Do not create another durable MinIO object unless a later requirement proves that it is necessary. Task 8 will consume the temporary PNG directly and close the handle after local OCR.

## Required outcome

```text
documentId
  -> short SQLite metadata lookup
  -> bounded MinIO PDF download to unique temp file
  -> exact size and SHA-256 verification
  -> bounded PDFBox load of the local file
  -> validate first-page dimensions before raster allocation
  -> render only page index 0 as RGB at fixed DPI
  -> bounded PNG write to unique temp file
  -> delete temporary PDF
  -> return AutoCloseable temporary-PNG handle
  -> caller closes handle
  -> delete temporary PNG
```

## Fixed architectural decisions

These are requirements, not choices for the implementer:

- Use Apache PDFBox `3.0.8`, artifact `org.apache.pdfbox:pdfbox`.
- Use file-backed PDF loading. Do not load the PDF from a `byte[]` or an `InputStream` that PDFBox copies into memory.
- Use PDFBox 3's `Loader` API with a file-backed source.
- Render only page index `0`.
- Render at `200` DPI.
- Render to `BufferedImage.TYPE_INT_RGB`/PDFBox `ImageType.RGB`; do not preserve alpha.
- Encode as PNG with the JDK ImageIO PNG writer.
- Keep the PNG temporary and local. Do not upload it to MinIO.
- Do not add a controller, endpoint, OpenAPI field, queue, exchange, message, outbox event, scheduled poller, or database table.
- Do not change `pos_document.processing_status`; it remains `PENDING` until the future OCR workflow owns that transition.
- Do not edit an existing Flyway migration. This task requires no migration.
- Keep rendering concurrency at one inside this application instance.
- Never use `readAllBytes()`, `Files.readAllBytes()`, `InputStream.transferTo()` into a byte-array output stream, or any equivalent whole-file buffering for the PDF or PNG.

The Apache PDFBox project currently identifies `3.0.8` as the current PDFBox 3.0.x release. Pin the version explicitly in `pom.xml`; do not use a version range.

## `DocumentRenderSource`


## Transactional metadata lookup

`DocumentRenderSourceService.load(UUID documentId)` must be `@Transactional(readOnly = true)` and must:

- Load the document together with its POS record and storage object using an explicit fetch-join repository method.
- Reject a missing document.
- Reject a document whose POS record is soft-deleted.
- Require storage content type `application/pdf`.
- Require a positive declared byte size not exceeding `max-pdf-bytes`.
- Require a lowercase or uppercase 64-hex-character SHA-256 value; normalize the returned snapshot to lowercase.
- Return `DocumentRenderSource`; never return an entity.
- Finish the transaction before any MinIO or PDFBox operation begins.

Do not enable Open Session in View and do not make associations eager globally.

## `StoredPdfMaterializer`

`StoredPdfMaterializer.materialize(DocumentRenderSource source)` streams the MinIO object to a unique temporary file and returns an `AutoCloseable` handle. The handle may be package-private if it is only passed to the renderer.

Required behavior:

- Create the file with `Files.createTempFile` using a fixed PII-free prefix and `.pdf.part` suffix.
- Open the MinIO stream through the existing storage adapter.
- Copy with a fixed-size buffer while counting actual bytes and updating SHA-256.
- Abort immediately when actual bytes exceed either `source.expectedByteSize()` or `max-pdf-bytes`.
- At EOF require actual size exactly equal to `expectedByteSize`.
- Compare the observed digest with `expectedSha256` using `MessageDigest.isEqual` on decoded digest bytes.
- Do not compare hashes as ordinary strings and do not use an S3 ETag.
- Close the MinIO stream and file output stream on every path.
- Delete the partial file on every exception.
- The returned handle's `close()` must be idempotent and delete the completed PDF temp file.
- Its `toString()` must not contain the object key, filesystem path, hash, filename, or other PII.

Do not infer `PDF_OBJECT_MISSING` by searching arbitrary exception-message text if the existing storage adapter can expose a typed missing-object condition. If the adapter cannot distinguish it without a small compatible change, add that typed distinction and update all existing adapter tests. Do not expose raw MinIO exception text.

## `PdfFirstPageRenderer`

`PdfFirstPageRenderer.render(MaterializedPdf pdf, UUID documentId)` must:

1. Acquire a fair semaphore configured with exactly one permit.
2. Load the local PDF through PDFBox using a file-backed API.
3. Reject encrypted/password-protected PDFs before rendering. Do not try passwords.
4. Require at least one page.
5. Inspect page `0` before calling a rasterizing method.
6. Calculate the effective output dimensions using the page crop box, rotation, and configured DPI.
7. Reject non-finite, zero, negative, or excessive page dimensions.
8. Require calculated width `<= max-width-pixels`, height `<= max-height-pixels`, and `width * height <= max-pixels`. Perform multiplication safely using `long`/checked arithmetic.
9. Render only page `0` with `PDFRenderer.renderImageWithDPI(0, dpi, ImageType.RGB)`.
10. Confirm the produced image dimensions are positive and still within every configured bound.
11. Write PNG to a unique PII-free `.png.part` temporary file through `BoundedOutputStream` capped at `max-png-bytes`.
12. Require `ImageIO.write(...)` to return `true`.
13. Verify the finished file begins with the eight-byte PNG signature and its actual size is positive and no greater than `max-png-bytes`.
14. Delete the input PDF temp file as soon as the PDFBox document has closed and rendering no longer needs it.
15. Return a `RenderedFirstPage` handle that owns only the PNG temp file.
16. Release the semaphore in `finally`, including load, render, encode, validation, interruption, and cleanup failures.

If the thread is interrupted while waiting for the semaphore:

- Restore the interrupt flag.
- Close/delete the materialized PDF.
- Throw the sanitized `RENDER_INTERRUPTED` failure.

Do not attempt to implement a fake timeout by abandoning a still-running PDFBox thread. Java cannot safely terminate that rendering thread. Process isolation and hard timeouts may be added later if operational testing proves them necessary.

## Dimension calculation

PDF page boxes use points, where 72 points equal one inch.

For unrotated dimensions:

```text
pixelWidth  = ceil(cropBoxWidthPoints  * dpi / 72)
pixelHeight = ceil(cropBoxHeightPoints * dpi / 72)
```

For normalized rotation `90` or `270`, swap width and height. Accept only rotations equivalent to `0`, `90`, `180`, or `270` after normalization; reject anything else as invalid.

Do not trust page dimensions solely because PDFBox accepted the document.

## `BoundedOutputStream`

Implement a small `FilterOutputStream` that:

- Counts every written byte for both `write(int)` and `write(byte[], int, int)`.
- Checks the limit before delegating the write.
- Uses overflow-safe arithmetic.
- Throws a dedicated internal limit exception before the count can exceed `max-png-bytes`.
- Does not include written bytes or paths in exception messages or `toString()`.

Permit one package-private constructor that accepts an initial count solely so overflow behavior can be tested without writing an enormous file. Production code must use the public constructor whose initial count is zero.

Test this class directly, including the single-byte method, array method, exact-boundary success, one-byte-over failure, and arithmetic near `Long.MAX_VALUE` without allocating a large array.

## `RenderedFirstPage`

Return an immutable `AutoCloseable` handle with:

```java
UUID documentId
Path pngPath
int widthPixels
int heightPixels
int dpi
long pngByteSize
```

Requirements:

- The handle exclusively owns `pngPath`.
- `close()` is idempotent and deletes the PNG.
- If deletion fails, throw or report a sanitized cleanup exception without including the path. Choose one behavior and test it.
- Do not expose a byte array convenience method.
- Do not expose the PDF temp path.
- `toString()` must omit `pngPath`.

`FirstPageRenderPreparationService.prepare(UUID documentId)` orchestrates the lookup, materialization, and rendering and returns this handle. It must not be annotated with `@Transactional`.

The orchestration must use nested try-with-resources so that:

- A metadata failure creates no temp file.
- A download failure leaves no temp file.
- A PDFBox failure deletes both the PDF and any partial PNG.
- A successful return has already deleted the PDF and leaves only the PNG owned by the returned handle.
- Closing the returned handle leaves neither file.

## Stable errors and logging

Define `RenderingException` with a fixed enum/code and fixed safe message. At minimum include:

| Code | Retryable | Meaning |
|---|---:|---|
| `DOCUMENT_NOT_FOUND` | No | Document is missing |
| `DOCUMENT_DELETED` | No | Parent POS record is soft-deleted |
| `PDF_METADATA_INVALID` | No | Persisted type, size, or hash is invalid |
| `PDF_OBJECT_MISSING` | No | Declared MinIO object does not exist |
| `PDF_SIZE_MISMATCH` | No | Actual bytes differ from persisted size |
| `PDF_HASH_MISMATCH` | No | Actual digest differs from persisted digest |
| `PDF_STORAGE_UNAVAILABLE` | Yes | Temporary storage/network failure |
| `PDF_INVALID` | No | Malformed, empty, or encrypted PDF |
| `PAGE_DIMENSIONS_INVALID` | No | Invalid or unsupported page geometry |
| `RENDER_LIMIT_EXCEEDED` | No | Pixel or PNG-byte limit exceeded |
| `RENDER_FAILED` | No | PDF cannot be rendered |
| `RENDER_INTERRUPTED` | Yes | Interrupted while waiting for the render permit |
| `TEMP_STORAGE_UNAVAILABLE` | Yes | Local temporary storage failed |

Do not put raw exception messages into the fixed detail. Preserve the original throwable only as an internal cause where useful.

Logs may contain generated UUIDs, stable codes, pixel dimensions, byte counts, and duration. Logs must not contain:

- Original filename or ZIP entry name
- Object key
- Temp path
- PDF text or image data
- SHA-256 value
- MinIO endpoint or credentials
- Raw PDFBox/MinIO/SQL exception messages

Do not log successful render output at `WARN` or `ERROR`.

### Renderer tests

- A one-page A4/Letter-like PDF renders page `0` at the expected dimensions for `200` DPI.
