# Task 6: Reliable ZIP consumption and PDF extraction

## Objective

Implement the first production RabbitMQ consumer. It consumes the existing identifier-only `IngestionRequestedMessage`, downloads the source ZIP from MinIO, safely extracts every PDF, stores each PDF as its own MinIO object, creates `storage_object` and `pos_document` rows, and exposes those rows through the existing document-list endpoint.

This task ends before OCR, page rendering, document classification, or metadata extraction.

## Required outcome

```text
RabbitMQ message
  -> validate message and claim job
  -> job RUNNING; POS record PROCESSING
  -> bounded source-ZIP download and integrity check
  -> existing secure ZIP validation
  -> bounded PDF extraction and MinIO upload
  -> one SQLite transaction for document metadata
  -> job COMPLETED; POS record remains PROCESSING
  -> RabbitMQ ACK
```

New documents must use `document_type=UNKNOWN` and `processing_status=PENDING`. `ingestion_job.COMPLETED` means archive extraction completed; the POS record remains `PROCESSING` because OCR is a later task.

## Strict scope

Implement only:

- One real listener for `pos.ingestion.jobs`
- Strict validation of the existing message and AMQP properties
- Source-ZIP download, size/SHA-256 verification, and revalidation
- Streaming extraction of multiple PDFs
- Deterministic document/storage UUIDs and PII-free MinIO keys
- PDF storage and transactional metadata persistence
- Bounded retry and DLQ handling
- Idempotent redelivery and scoped MinIO compensation
- Persisted `GET /api/v1/pos-records/{id}/documents`
- Unit, SQLite, real MinIO, real RabbitMQ, and whole-stack tests

Do not implement OCR, PDF-to-image rendering, classification, vLLM, OpenAI calls, search, PATCH/DELETE persistence, authentication, another message type, another queue, or OpenAPI changes. All unrelated dummy endpoints remain unchanged.

## Configuration

Add validated properties:

```yaml
app:
  ingestion:
    consumer:
      enabled: ${INGESTION_CONSUMER_ENABLED:true}
      concurrency: 1
      prefetch: 1
      max-attempts: 3
      initial-backoff-ms: 1000
      backoff-multiplier: 2.0
      max-backoff-ms: 5000
      max-message-bytes: 4096
```

Expose `INGESTION_CONSUMER_ENABLED` in Compose, defaulting to `true`. Keep SQLite's pool size at one. Do not use unbounded requeue.

## Message validation

Accept the raw AMQP `Message` and parse it with the configured Jackson mapper. Before processing, require:

- Body no larger than `max-message-bytes`
- JSON content type and persistent delivery mode
- Exactly `eventId`, `jobId`, `posRecordId`, `schemaVersion`, `occurredAt`; reject missing, null, duplicate, or extra properties
- Schema version `1`
- `messageId == eventId`
- `correlationId == jobId`
- AMQP type `INGESTION_REQUESTED`

Never log the body or untrusted headers. Malformed messages must reach the existing DLQ and must not update arbitrary rows.

## Job claiming and state

Use a short transaction to load the job, record, and source storage metadata. Verify the message's job/record relationship and reject soft-deleted records.

| Existing job state | Action |
|---|---|
| `QUEUED`, `RETRY_SCHEDULED` | Start attempt |
| `RUNNING` | Resume after crash; increment attempt |
| `COMPLETED` with documents | ACK as idempotent no-op |
| `COMPLETED` without documents | Permanent state-conflict failure |
| `FAILED` | ACK as terminal no-op |

Add intention-revealing entity methods: `startAttempt(now)`, `complete(now)`, `fail(now, code, safeMessage)`, `markProcessing(now)`, and `markFailed(now)`. Increment the attempt exactly once per listener attempt. Never hold a transaction during MinIO, ZIP, RabbitMQ, or retry waits.

## Source materialization

Stream the source object from MinIO into an owned temporary file while counting bytes and calculating SHA-256. Enforce the existing 10 MiB compressed limit using bytes actually read. Compare exact size and digest with `storage_object`; use constant-time digest comparison. Close the MinIO stream and delete partial/finished temp files on every path.

Then run the existing `ZipArchiveValidator` against the downloaded file. Do not weaken its entry-count, path, suffix, magic, per-entry, total-expanded, or compression-ratio protections.

Use stable errors such as `SOURCE_ARCHIVE_MISSING`, `SOURCE_ARCHIVE_SIZE_MISMATCH`, `SOURCE_ARCHIVE_HASH_MISMATCH`, `SOURCE_ARCHIVE_INVALID`, and `SOURCE_STORAGE_UNAVAILABLE`. Never store raw exception text.

## PDF extraction

Process non-directory entries in central-directory order and assign zero-based sequence numbers. For each PDF:

1. Keep only the final filename segment as sensitive SQLite metadata; never use it as a path.
2. Stream to one unique temporary PDF while calculating SHA-256 and enforcing all effective limits on every read.
3. Verify `%PDF-` and exact byte count.
4. Upload with `application/pdf` and known size.
5. Delete the PDF temp file before processing the next entry.

Never call `readAllBytes()` or retain whole ZIP/PDF contents in heap. Peak temporary storage should be one ZIP plus one PDF.

## Deterministic identity and keys

Derive `documentId` from a fixed namespace plus `posRecordId` and sequence, and derive `storageObjectId` from a different fixed namespace plus `documentId`. Pin outputs in tests. Inputs must contain only fixed ASCII labels, generated UUIDs, and sequence numbers—never filenames, eRef, policy data, names, or hashes.

Required key:

```text
documents/{posRecordId}/{documentId}.pdf
```

The same redelivery must produce the same IDs and key. An orphan from a crash may be safely overwritten with bytes produced from the immutable source ZIP. Do not treat an S3 ETag as SHA-256.

## Persistence and compensation

After all PDF objects are stored, use one transaction to create/reconcile all `storage_object` and `pos_document` rows, mark the job `COMPLETED`, and keep the record `PROCESSING`.

Existing deterministic rows may be reused only when every immutable field matches. Any mismatch is `EXTRACTION_STATE_CONFLICT`; never overwrite conflicting metadata. Roll back the complete metadata transaction on failure.

Track objects newly created during the current attempt. On later upload/database failure, delete only those keys. A compensation failure preserves the original failure and logs only the generated UUID key for orphan recovery.

Do not edit V1/V2. If a schema change appears necessary, stop and propose the exact V3 migration first.

## Retry and DLQ

Use one listener thread, prefetch one, automatic ACK only after normal return, and bounded stateless retry: three total attempts with 1s/2s/capped-5s backoff.

Classify integrity, malformed archive/message, deleted record, ID mismatch, and state conflict as nonretryable. Storage/network and genuinely temporary database failures may be retryable. After exhaustion, a custom recoverer uses a new short transaction to mark an identifiable job/record failed with fixed sanitized fields, then rejects without requeue so the original message reaches `pos.ingestion.dead`.

Do not allow listener/framework exception logging to expose filenames, entry paths, SQL/storage messages, endpoints, hashes, credentials, or temp paths.

## Document-list endpoint

Make `GET /api/v1/pos-records/{id}/documents` real:

- Return 404 for a missing/soft-deleted record
- Return persisted documents ordered by `sequence_number ASC`
- Return `[]` before extraction
- Map inside a read-only transaction without Open Session in View
- Do not contact MinIO or expose credentials/presigned URLs

Update the old dummy-document MVC test. Other Task 1 endpoints remain dummy.

## Whole-stack verification

Preserve the corrected Compose-project guard and existing persistence checks. Test two phases:

1. Consumer disabled: upload fixture, observe one queued identifier-only message, restart RabbitMQ, and prove the persistent message survives.
2. Consumer enabled: wait for job `COMPLETED`; assert two ordered `UNKNOWN/PENDING` documents, empty main queue/DLQ, source plus two UUID-keyed PDFs in MinIO, byte equality, persistence across MinIO/backend restart, and duplicate-message idempotency.

Use bounded polling and no `jq` requirement. Do not print credentials, hashes, or document contents.

## Acceptance criteria

- Real listener consumes the existing message with strict validation.
- Source ZIP is streamed, integrity-checked, and revalidated.
- Multiple PDFs are streamed and stored byte-for-byte under deterministic UUID-only keys.
- One storage/document row exists per PDF; documents begin `UNKNOWN/PENDING`.
- Job ends `COMPLETED`; POS remains `PROCESSING`.
- Redelivery is idempotent and crash orphans are reusable.
- Partial failures leave no partial SQLite metadata and compensate new objects.
- Retry is bounded; terminal messages reach the DLQ with sanitized state.
- Document listing returns persisted ordered rows.
- No OCR/rendering/classification is added.
- All Maven, SQLite, real MinIO/RabbitMQ, and whole-stack tests pass with zero skips.

## Required final report

Report handwritten files, resolved/new dependencies, consumer/retry/ACK behavior, validation and extraction limits, deterministic key scheme, lifecycle transitions, transaction/idempotency/compensation behavior, every verification command, final test counts, both whole-stack phase results, and every deviation.

## Stop conditions

Stop instead of improvising if the message or OpenAPI contract must change, safe bounded retry is unavailable in the managed AMQP API, extraction would require whole-file buffering, MinIO streaming requires an incompatible adapter change, a migration appears necessary, a requirement reaches into OCR/classification/authentication, a core dependency version must change, or the baseline fails.
